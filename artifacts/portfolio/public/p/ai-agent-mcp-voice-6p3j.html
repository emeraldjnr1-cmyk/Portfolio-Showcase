02 · Your problem

The agent works, but not reliably enough to build on.

"First, the agent needs to be more stable. That means fixing issues, better monitoring and handing the conversation to a person when it isn't sure."

Your job post, Upwork, November 2026
Pain 01

Issues in a live agent

The agent is already talking to your customers, so every open issue happens in front of them, not in a test environment.

Cost today: customer conversations that go wrong while the issue is still open.
Pain 02

Not enough monitoring

Without clear monitoring, a failed API call, a slow response or a bad answer is easy to miss until someone notices it by chance.

Cost today: problems found late, often by a customer before your team.
Pain 03

No handoff when it is not sure

When the agent is unsure, it should pass the conversation to a person. Without that, it either guesses or leaves the customer stuck.

Cost today: wrong answers and lost bookings that a person would have handled.
Pain 04

The roadmap waits on a fragile base

MCP for the CRM, RAG over your documents, voice for calls and roles on the dashboard all sit on top of the agent and your data. Building them on a shaky base multiplies the problems.

Cost today: new features on hold, or built on something that is not yet safe to extend.

05 · How the work runs

Three stages, stability before features.

I work in Claude Code every day, in your repo, on branches you can review. Nothing reaches production without a test, and anything risky goes to a staging copy first.

01

Stabilise · month 1

Week 1 is the audit and the worst fixes. Weeks 2 to 4 add the monitoring and the handoff.

  • Stability audit: code, logs, prompts, tool calls and recent conversations, with a ranked issue list
  • Fixes in priority order, each with a test that reproduces the issue
  • Monitoring: errors, latency, tool failures and handoffs per conversation, with alerts
  • Human handoff below a confidence line you agree, with a summary for the person taking over
02

Connect · month 2

Claude gets safe access to your CRM, and your documents become answerable.

  • MCP server for the CRM: read-scoped tools first, write actions only after a person confirms, deletes not exposed
  • Audit log of every tool call: who, which tool, what changed
  • RAG assistant over your documents in Supabase with pgvector, every answer showing its source, no source means no answer
03

Extend · month 3

The dashboard gets proper access control, and the agent starts answering the phone.

  • Supabase roles and RLS on the admin dashboard, so access is enforced in the database, not only hidden in the interface
  • Voice assistant for calls and bookings. To be straight with you: I have not shipped a voice assistant for a client yet. I would build it on a managed voice layer such as Vapi or Twilio, with Claude behind it and bookings made through your calendar API, reusing the same tools, handoff and monitoring from stages 1 and 2
  • New monthly tasks from your list once the roadmap is in place
